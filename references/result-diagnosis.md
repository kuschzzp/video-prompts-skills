# 根据成片偏差迭代

用户报告“生成不对”时使用。只根据能看到、听到或用户明确描述的结果判断，不假装已经播放不可访问的视频。

## 收集最小证据

读取已有提示词、模型版本、平台、设置、素材用途和偏差发生时间。缺少视频时可依据用户描述提出暂定方案，注明证据来源；不要为了填写所有字段反复追问。只有关键缺失妨碍定位时才询问。

把原提示词作为对照保留。使用 [迭代记录](../assets/iteration-record.md) 记录有意义的实验；用户未要求存档时可直接在回复中简短列出，无需每次创建文件。

如果视频由另一个 Agent 执行，区分用户原始需求、局部修订说明、实际提交的合并正文及工具参数。未取得工具请求时标记未知，不能仅凭“其他不变”推断旧要求已继承或已丢失。编辑模式还需核对真实绑定的源视频及修改范围。

## 观察与假设分开

| 观察到的偏差 | 可检查的假设 | 最小修改方向 |
| --- | --- | --- |
| 非说话人也动嘴 | 说话人与台词绑定不清、轮次重叠 | 明确轮次及听者反应，不改变台词 |
| 订书机尚未压下就响 | 音效只写在全程摘要、缺触发点 | 将短响绑定钉脚穿纸的时刻 |
| 换镜后道具换手 | 前后镜头缺少交接状态 | 只补持物手和动作阶段 |
| 人物形象漂移 | 素材未绑定、引用不一致或能力局限 | 先核实输入映射，再补身份锚点 |
| 镜头太忙、动作不完整 | 同时承载过多事件 | 简化无必要的运镜或调整动作先后 |
| 独立片段的场景或道具接不上 | 本段缺必要锚点、初态与上段终态不符，或实际参考未绑定 | 按 [片段交付检查](segment-checks.md) 补必要上下文和变化，不按词面删除指代或重演交接 |
| 句尾被截断或台词来不及完成 | 文本或音轨超过片长、入口时长设置不符，或生成偏差 | 对照真实时长、音轨与设置，再按容量重新分段，不仅修改标题秒数 |
| 关键细节在暗处读不到、切镜后光线跳变 | 光源、遮挡、材质反光或曝光描述与机位不相容 | 按 [光影与色彩](lighting-and-color.md) 调整受光和观察位置，区分有意光变与连续性错误 |
| 配乐盖过台词 | 强弱层级不明确 | 降配乐相对音量，必要时提出混音 |
| 尾帧不一致 | 只用普通参考、时间写错或生成偏差 | 先核对模式和结束时间，不承诺加词即可解决 |
| 远处主体要求的细节读不到 | 景别、焦点或遮挡与信息目的不合 | 按 [视觉与空间](visual-continuity.md) 调整观察尺度，不只加“清楚” |
| 持物突然悬空或多出一只手 | 动作需要的手被占用、承重没有交代 | 按 [动作与素材](action-and-assets.md) 补放置或交接阶段 |
| 手移动、布料却停在原处或只翻边 | 握持点、相对轨迹或接触到形变的关系不清，也可能是执行偏差 | 补接触如何持续、哪部分随手位移及可见终态，不只加“流畅” |
| 布料已堆起，要求露出的部位仍未露出 | 中间形变被误当终态，或覆盖边界、机位与操作路径未对应 | 分别核对布料位置、覆盖范围和关键部位可见性，必要时调整路径或换握 |
| 物体直接回到原状，没有恢复过程 | 返回动作被省略、跳切掩盖中间状态或任务容量不足 | 写清重新抓握、展开与目标覆盖的变化，关键过程保留可见，不强制所有动作沿原路返回 |

这些只是待验证的可能原因，不能仅凭一次失败断言模型缺陷，也不能把同一次成功提升为通用规则。

## 查看实际动作与时长

有可访问的原片和工具时，先连续播放，再围绕关键事件查看证据：接触前、握持建立、滑动或形变中、越过关键部位、恢复后。低频抽帧可初筛姿态和出画；每秒一帧属于稀疏抽样，不是逐帧检查，不能据此证明中间没有跳变。必要时在相关时段加密抽帧或逐帧查看，并结合连续播放与声音判断；频率按动作速度选择，不固定为每秒一帧。

柔软物体分别看手与物体的相对位移、覆盖边界、褶皱及接触连续性。机位变化或遮挡可能影响判断，无法看清就报告证据不足；不把画面中的尺寸变化直接当成真实形变。镜头只要保留关键证据即可，不因一次失败把所有操作改成固定机位或一镜到底。

输出时长反复短于要求时，分别记录计划时长、工具实际提交的时长设置及文件实测时长；有后处理时另核对生成原片。检查入口范围与默认值、Agent 参数转译、模式或源视频时长、后期裁切等可能原因。未取得请求与媒体元数据时保留不确定性，不能断言平台上限就是10秒，也不能把正文改成15秒视为已经修复。

按目标分别结论：动作体验改善、覆盖终态未达到、姿态偏移、时长不足可以同时成立。用户接受某一改善，不等于全部约束已满足。只有用户的文字复现时注明“依据用户报告”，不声称自己已看片或完成抽帧。

## 试改流程

1. 锁定最影响任务目标的一项偏差，保留其他成功部分。
2. 只改变一个变量或一组不可分割的因果描述；保留版本对照。
3. 比较设置、素材和提示词是否一致。平台支持种子时可固定以减少变量，但不保证完全确定性。
4. 评价同一时点的可见/可听结果，记录改善和退化；未重新生成就是“待验证”。
5. 提示词无法控制的问题，提出替代模式、拆段或后期方案及代价。是否执行按当前用户授权，文本修复不自动触发重新生成。

没有新证据或重复尝试没有改善时停止同一路径，报告剩余问题；不无限追加形容词或重复付费生成。维护经验时标明模型、版本、模式、证据和适用范围。

用户只要求修改某段时，保留其他段落与编号；检查改动的时长、身份状态和道具终态是否影响下一段，只联动必要内容。重写后仍属于待验证的提示词，不能把文本更完整当作成片已经改善。
