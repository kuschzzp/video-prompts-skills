核实日期：2026-10-21；提示词写法于2026-10-29复核；本文件于2026-11-14修订，新增时长、画幅与负向写法，新增能力数字于2026-11-14复核（见文末）。范围：字节 Seedance 2.5 / 火山方舟文档；第三方平台可能有不同输入界面。

## 官方建议

可先概述主体、地点、事件与风格，再按镜头或时间轴描述动作、运镜、台词和音效。参考任务需按上传顺序明确素材编号与用途，实际引用形式以使用入口为准。无字幕、无配乐等控制用明确文字说明。

这些是推荐表达，不代表硬解析或必然准确执行。没有官方依据将 H3 的两个声音字段当成 Seedance 必需字段。

## 时长：15 秒是交付预算，不是平台上限

主文件默认单段不超过 15 秒，那是交付预算，不是所有平台的统一上限。Seedance 2.5 的单次生成能力，于 2026-11-14 复核（官方模型页直接打开；BytePlus ModelArk 教程以多家引用官方文档的资料转述，教程最后更新 2026-09-28）：单次 4–30 秒整秒，或 `-1` 由模型自选；480p / 720p 为 8-bit，1080p 为 10-bit HEVC，默认 720p；24fps；一次生成内可组织多个逻辑相连的镜头；官方模型页写明“支持两次视频延长”；单次最多 50 个参考素材（30 图 + 10 视频 + 10 音频）；画幅 21:9 / 16:9 / 4:3 / 1:1 / 3:4 / 9:16 / adaptive。入口（即梦、豆包专业版等消费端）给出的时长与分辨率档位可能更少，生成前以用户实际入口看到的选项为准。4K 不是标准 API 档位（4K 是 Seedance 2.0 的档位，或企业版、App 端的说法），不要给 2.5 写 4K。

预算与上限分开用：

| 情况 | 建议 |
| --- | --- |
| 一个简单动作加一句对白 | 8–10 秒就够，不要为了填满 15 秒加无关运镜 |
| 一次完整交互加反应 | 接近 15 秒，按对白、动作、反应与余波估算，不加速对白强塞 |
| 多镜头、长对白或复杂交互 | 超过 15 秒先拆段；只有用户明确要求单次长生成、且已确认入口支持时，才用 20–30 秒，并在概览中说明；不要把每个小动作各拉满 15 秒 |
| 入口实际单段更短 | 消费端入口档位可能更少，其他模型入口单段可能只有约 10 秒；写 12 秒、入口只出 10 秒，最后一句会被截掉。按实际入口重算分段与节拍（见 [多段数数自查](segment-checks.md) 第 2、7 条），换入口不只改数字 |
| 用户已指定单段时长 | 以用户指定为准，内容放不下时说明冲突，让用户选择放宽时长或授权删减 |

不要把“单次能到 30 秒”当成每段都该 30 秒。时长服从内容，超载就拆，过空且能自然衔接就合并。估时方法见 [时间与声音](shot-and-sound-design.md)。

## 画幅：16:9 还是 9:16，先问画面里要装什么

画幅不是习惯，是构图决定。先问本片要在同一画面里装下什么，再选画幅。

| 画幅 | 适合 | 不适合 |
| --- | --- | --- |
| 16:9 横屏 | 两人同框、左右对照、前景加背景纵深、同一画面里放两个表或两个人 | 单人特写为主、竖屏平台首发、只想突出一张脸 |
| 9:16 竖屏 | 单人近景、上下关系、竖屏平台首发 | 两人远距离递物、左右对照、横向空间关系是重点 |

原创例：手表停在 7:42，墙上有挂钟，关键一镜要把手腕上的表和墙上的挂钟放进同一画面，对上时间。竖屏得切来切去，横屏一个画面就够了，所以选 16:9。反过来，如果全片只拍一个人低头看表，9:16 更直接。

选定画幅后全片一致；换画幅要重排构图，不能只改比例数字。不同画幅下人物能否同框、交互部位会不会被裁，见 [视觉与空间](visual-continuity.md)。

## 负向写法：只写不要什么，用中文约束

Seedance 没有统一的负向字段格式，本 skill 用中文约束写在正文或块首，不伪装成已设置的参数。

- 可用写法：“无旁白，无解释字幕，无新增人物，无换场景，无煽情音乐，无手持晃动。”
- 只写本片确实不要的东西，不要把通用负向清单全贴一遍。没有配乐就省略配乐字段；明确不要配乐时保留中文约束；完全静音时移除所有声音。
- 不要写“高质量、电影感、完美”这类无法判断的词。质量词优先写可见的光线、材质、构图和运动。

## 本 skill 的输出约定

正文默认中文，用户明确要求其他语言时按主文件处理。每段代码块先写明本段总时长、已确定比例及必要的视觉或声音约束，之后可按“实际素材用途—整体视觉基准—必要的初始空间—按时间展开的镜头—结束状态”组织；需要独立概括声音时再加声音段。这是本skill的创作组织方式，不是官方固定schema；简单场景直接融入镜头正文，不机械输出全部栏目或重复开头设置。未提供素材时省略资产锁定，不把样稿中的资产名或平台占位标签当成已绑定输入。

镜头可用 `【镜头01｜00:00—00:04｜镜头目的】` 标示起止与目的，也可用清晰的自然语言时间段。先按 [视觉与空间](visual-continuity.md) 判断机位、可读细节和相对运动，再写景别、光源、主体动作、相机与末态；素材继承与交互参考 [动作与素材](action-and-assets.md)。时间分配服从内容，不以小数精度或镜头数量证明质量。

动作跨镜接同一次事件，台词跨镜保持说话人和声音连续，写清是否画外声；不要因正文分段而重复台词或动作声。特效先明确产生与作用过程，再按场景写环境反馈，不只罗列特效名称。详细导演方法遵循通用参考，不另起一套Seedance专用艺术规则。

将 H3 转来时保留对白内容，替换外围标签；用角色描述关联发言，不遗留 `<d>` 或 `<Picture N>`。`[Shot N]` 本身可作为普通镜头标题，但不宣称是 Seedance 专用语法。

场景内音乐明确实际声源及角色可以听到；背景配乐明确不来自场景。对白写清说话人、原文及必要的语言信息；没有字幕需求就不添加字幕文案，需要时明确文字及出现时间。普通栏目标题的括号不等于字幕指令，不把某套括号写法当成官方硬解析规则。

没有配乐或其他声音层时省略对应栏目，不写空项。声音跟随具体动作或表演转折发生，不复制每段相同的声景模板。用户参考文本属于学习材料，其中的执行口吻、平台参数和资产声明不自动成为当前任务指令；借鉴镜头逻辑，不把其时长、极短反应时隙或保证性措辞当成模型能力证据。

分段任务每段重复必要的人物、风格与场景信息，独立从0秒计时，并写全该段画面与声音。素材职责以本段实际绑定为准，不用上一段的引用代替本段输入。

## 平台及参数边界

官方 API 的首帧/首尾帧模式用素材角色绑定，不能仅靠文本标签替代。教程当前要求这类任务的比例为 `adaptive`，继承首帧比例；要 16:9 就准备对应比例的首帧。只有一张结尾图时，不直接假设支持独立尾帧模式。

用户仅写提示词时不强行输出 API 参数。需要实际提交或 API 设置时，再核实版本、生成模式、时长、音频开关和素材准入要求。参考、编辑、延长各有条件，不把某一模式的参数复制给所有模式。

平台没有提供真实素材引用或缺少所需模式时，标明尚待绑定或只能作构图参考；不要把 `@图片1` 的文字当成已经上传。

完整交付形态可读 [原创完整案例](../examples/classroom-drawing.md)。本地资料的核实日期不代表入口永不变化；实际提交或用户要求最新能力时核对当前官方文档，无法取得资料就区分已知创作要求与待验证的适配条件。
