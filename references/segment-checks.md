# 多段提示词的交付检查

多段创作、换生成入口或局部修订影响相邻片段时使用。检查实际提交的文本与素材是否足够，不假定生成模型拥有助手的对话历史。首尾帧、参考视频、编辑或延长模式的上下文来自真实绑定的输入。

本文件补充主文件的交付检查，不另设剧情模板或固定动作数量。普通任务在内部核对即可；只报告与当前任务有关的冲突或待验证项。

## 1. 单段上下文是否完整

- 单独复制本段代码块，仍能确定必要人物、场景、已知设置、起始状态及实际素材用途。
- “继续”“同一个”等词可以指向本段已经交代的对象；问题是依赖块外未知信息，不是出现某个词。用户原对白里的这些词保持原文。
- 必要锚点保持语义与身份一致，无须逐字复述所有背景。动态状态按本段初态更新，不把上一段的旧姿态永久写进人物定义。
- 已提供的道具可以从开场就在场，无须每段重新拿出、交接或解释来源。新出现的物体、图形或声音需要与场景、动作或明确的视觉设计相符。
- 局部修订说明可以只给差异；交给生成 Agent 实际执行时，要核对它使用的是合并后的完整正文和设置。独立文生视频不把“其他保持不变”当作完整输入；原视频编辑模式则核对源视频及编辑范围，不假定工具持有先前上下文。

## 2. 时间是否容纳实际内容

先按 [时间与声音](shot-and-sound-design.md) 估算完整对白、动作先后、可并行部分和反应，再核对时间轴；不以“每个动作固定3秒”或节拍数替代估时。一句长对白可能超过整段，多个短动作也可能自然并行。

容量不足时先缩减无表达作用的相机运动和空耗；仍不足就拆段。用户锁定剧情或单段时长时，说明冲突，不自行砍对白和关键事件。入口上限改变后重新规划内容与切点，不只改标题数字。

多段总长核对各段之和；有剪辑重叠就说明其时长。每段从0开始，镜头、对白及尾帧目标不能超过本段结束时间。

段内边界按动作与停顿选择整数或小数秒，不为凑整数改变节奏；生成总长参数与输出实测时长分别核对，详见 [时间与声音](shot-and-sound-design.md)。输出短于要求时，不能只改正文的时间标签就称已修复。

## 3. 状态与动作是否接续

逐段对照上一段终态与本段初态：身份、服装、位置、朝向、持物、接触、光源及声音是否能接上。跨时空转场按故事标明变化，不要求回忆或省略段保持相同地点和姿态。

切镜接同一次动作的下一阶段，避免重新起手、交接或落地。原有状态与计划动作有冲突时，先分清“开场已经发生”和“本段即将发生”，再修正描述。细查见 [视觉与空间](visual-continuity.md) 与 [动作与素材](action-and-assets.md)。

柔软物体另查接触点、手的相对轨迹、物体是否随接触位移或形变，以及目标覆盖范围；有恢复要求时不能省略恢复过程。姿态、物体终态和动作体验分别验收，不用“看起来流畅”代替其余目标达标。

拟用上一段末帧衔接时，先记录依赖；实际生成后查看真实输出，再确认模式支持并绑定。写出衔接方案不等于已经取得素材或能保证无缝。

## 4. 镜头与声音是否服务表达

- 固定镜头可以通过人物行动、入画、表演和声音增加信息。需要运动时按 [镜头语言](camera-language.md) 检查目的、起幅、触发、路径与落幅；不按运动动词数量判定成败。
- 组合运动核对各部分如何协同、能否看清关键动作、是否挤占反应时间。复杂度超过入口的稳定能力时，保留表达重心，简化运动或拆镜。
- 对白、歌词与声音身份保持原文及顺序；不要求每句对应一个画面动作。回忆性旁白、听者反应和有意声画对照均可成立，说明必要的时间与叙述关系即可。
- 用户明确要求动作与词句同步时，按实际音轨或自然语速核对具体时点。只有文字时注明属于估时，不把歌词换行数当成演唱时长，也不以时间码保证精确同步。
- 同步动作声对应实际触发；跨镜对白不重说，跨段声桥写明输入或后期依赖。发现句尾被截时，同时检查文本容量、音轨时长、生成时长及入口设置，不直接认定是某一原因。

## 如何处理检查结果

缺失必需上下文、超出已知入口限制、动作或约束互相冲突时，先修正或明确报告冲突。模型执行精度、身份保持或精密声画同步属于待成片验证的风险，不用增加禁词或固定配额冒充解决。

本轮检查方向参考 [PR #1](https://github.com/kuschzzp/video-prompts-skills/pull/1)，重新整理为按上下文判断的方法；单次任务的失败记录不作为所有模型和题材的硬限制。
